# Додаток И — Діаграма пакетів (попередня архітектура)

UML package diagram. Reflects the real, simplified implemented architecture. The server is layered (routes → middlewares → services → repositories → DB), and every layer is sliced into the SAME set of business domains — the actual folders of `backend/src/features/`. So inside each server layer the diagram shows nested domain packages, not just the layer name. The client side shows the actual frontend packages (`frontend/app/*`).

Draw packages as folder-tab rectangles; nested packages inside their parent; dependencies as dashed arrows `-->` (depends on). Layout: «Клієнт» on top, «Сервер» below, БД / файлове сховище / зовнішні сервіси at the bottom.

## Домени (спільний перелік для всіх шарів сервера)

11 бізнес-доменів = папки `backend/src/features/`:

1. «Користувачі» (users)
2. «Клієнти» (clients)
3. «Запрошення» (invitations)
4. «Сесії» (appointments)
5. «Інтерактивна дошка» (whiteboard)
6. «Вкладення» (attachments)
7. «Файли» (files)
8. «Асоціативні зображення» (associative-images)
9. «Дашборди» (dashboard)
10. «Прогрес» (progress)
11. «Сповіщення» (notifications)

## Пакет «Клієнт (браузер)» — SPA

- **Сторінки** (routes/)
  - вкладений **Спільні сторінки** — вхід, вибір ролі, прийняття запрошення
  - вкладений **Сторінки психолога** — дашборд, клієнти, профіль клієнта, сесії, жива сесія з дошкою, запрошення, асоціативні зображення
  - вкладений **Сторінки клієнта** — дашборд, сесії, деталі сесії, жива сесія, прогрес, профіль
- **Компоненти інтерфейсу** (components/)
  - вкладені: **Базові UI-компоненти** (ui), **Спільні компоненти** (common), **Компоненти дошки** (whiteboard), **Форми сесій** (session-form), **Форми вкладень** (attachment-form, attachments)
- **Хуки** (hooks/) — завантаження поточних ресурсів, синхронізація дошки, захист маршрутів за роллю
- **Контекст автентифікації** (contexts/auth-context)
- **API-сервіси** (services/) — спільний HTTP-клієнт + модуль на домен
- **Моделі** (models/)

Залежності клієнта:
- Сторінки --> Компоненти інтерфейсу
- Сторінки --> Хуки
- Сторінки --> Контекст автентифікації
- Хуки --> API-сервіси
- Контекст автентифікації --> API-сервіси
- API-сервіси --> Моделі

## Пакет «Сервер» — шари з доменними пакетами всередині (зверху вниз)

- **Шар маршрутів (HTTP API + WebSocket)** — валідація запитів, HTTP-відповіді. Вкладені пакети маршрутів за доменами (10 штук): «Маршрути користувачів», «Маршрути клієнтів», «Маршрути запрошень», «Маршрути сесій», «Маршрути дошки (WebSocket)», «Маршрути вкладень», «Маршрути файлів», «Маршрути асоціативних зображень», «Маршрути дашбордів», «Маршрути прогресу». Домен «Сповіщення» маршрутів НЕ має (запускається планувальником, а не HTTP-запитами).
- **Проміжні обробники (middleware)** — без доменного поділу: сесія користувача, авторизація, активна роль, звʼязок психолог–клієнт, володіння файлами, перевірка вкладення.
- **Шар сервісів (бізнес-логіка)** — вкладені пакети сервісів за доменами (11 штук): «Сервіс користувачів», «Сервіс клієнтів», «Сервіс запрошень», «Сервіс сесій», «Сервіс дошки», «Сервіс вкладень», «Сервіс файлів», «Сервіс асоціативних зображень», «Сервіс дашбордів», «Сервіс прогресу», «Сервіс сповіщень».
- **Шар репозиторіїв (SQL-запити)** — вкладені пакети репозиторіїв за тими самими 11 доменами: «Репозиторій користувачів», …, «Репозиторій сповіщень». Без бізнес-правил.
- **Моделі даних** — без доменного поділу на діаграмі; примітка: кожен домен має власний модуль моделей.
- **Інфраструктура** — конфігурація, better-auth, клієнт Google Calendar, поштовий клієнт (Brevo), журналювання, помилки.
- **Планувальник завдань (cron)** — тик формування нагадувань + тик надсилання листів.

Залежності сервера (лише «вниз», малювати МІЖ ШАРАМИ, а не між окремими доменними пакетами — кожен доменний пакет маршрутів залежить від сервісу свого домену, кожен сервіс — від репозиторію свого домену; на діаграмі це показано однією стрілкою шар-до-шару):
- Шар маршрутів --> Проміжні обробники
- Шар маршрутів --> Шар сервісів
- Планувальник завдань --> Сервіс сповіщень (стрілка саме до доменного пакета)
- Шар сервісів --> Шар репозиторіїв
- Шар сервісів --> Інфраструктура
- Шар маршрутів --> Моделі даних ; Шар сервісів --> Моделі даних ; Шар репозиторіїв --> Моделі даних

## Нижній ряд

- Вузол **База даних PostgreSQL**: Шар репозиторіїв --> База даних PostgreSQL
- Вузол **Файлове сховище** (локальний диск): Сервіс файлів --> Файлове сховище (стрілка від доменного пакета)
- Пакет **Зовнішні сервіси**: **Google OAuth 2.0**, **Google Calendar API (Google Meet)**, **Поштовий сервіс**
  - Інфраструктура --> кожен із трьох зовнішніх сервісів

## Міжчастинна залежність

- API-сервіси (клієнт) --> Шар маршрутів (сервер), підпис стрілки: «HTTP-запити та WebSocket-зʼєднання»

Нічого поза переліченим не додавати.
