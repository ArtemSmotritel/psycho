# Додаток К — Діаграма діяльності пакету «Інтерактивна дошка»

UML activity diagram with two swimlanes: **Клієнт (браузер)** and **Сервер**. Start ● at top of Клієнт lane. Use diamonds ◇ for decisions, rounded rectangles for actions, ◉ for end.

## Доріжка «Клієнт»
1. ● Початок
2. [Дія] Відкрити сесію → встановити WebSocket-з’єднання до `/api/whiteboard/‹id_сесії›`
3. → (перехід на доріжку «Сервер»: автентифікація)
4. [Дія] (після отримання дозволу) Отримати повідомлення `scene_init` → відобразити повний стан дошки
5. [Дія] Взаємодія користувача (малювання / фігура / текст / стирання / рух курсору)
6. ◇ Це рух курсору?
   - Так → [Дія] Надіслати `cursor {x,y}` (не частіше 1 раз/50 мс) → назад до п.5
   - Ні → продовжити
7. ◇ Сцена змінилася (сигнатура відрізняється) і масив не порожній?
   - Ні → назад до п.5 (придушення «відлуння»)
   - Так → [Дія] Надіслати `elements` (+ `files`, якщо є нові) → на доріжку «Сервер»
8. [Дія] (паралельно) Отримати `elements` / `files` / `cursor` іншого учасника → оновити сцену / накладку курсорів → назад до п.5
9. ◇ Психолог завершує сесію?
   - Так → [Дія] Растеризувати дошку у PNG-знімок → надіслати на сервер → ◉ Кінець
   - Ні → назад до п.5

## Доріжка «Сервер»
A. [Дія] Прийняти запит на з’єднання → перевірити сесію користувача
B. ◇ Автентифіковано? Учасник сесії? Сесія активна?
   - Ні (будь-яка умова) → [Дія] Закрити з’єднання з кодом порушення політики → ◉
   - Так → продовжити
C. [Дія] Знайти «кімнату» за id сесії
D. ◇ Кімната існує в пам’яті?
   - Ні → [Дія] Підвантажити стан дошки з БД (поля елементів/файлів сесії) → створити кімнату
   - Так → продовжити
E. [Дія] Додати з’єднання до кімнати → надіслати цьому клієнту `scene_init` (повний стан)
F. [Дія] (цикл обробки повідомлень) Отримати повідомлення
   - `elements`/`files` → оновити стан кімнати в пам’яті → ретранслювати іншому учаснику → запланувати відкладений запис у БД (debounce ~3 с)
   - `cursor` → додати userId/userName → ретранслювати іншому учаснику
G. ◇ Учасник від’єднався?
   - Ні → назад до F
   - Так → [Дія] Прибрати з’єднання
H. ◇ Це був останній учасник?
   - Так → [Дія] Примусово зберегти стан у БД → вивантажити кімнату → ◉
   - Ні → назад до F

Підпис: стан дошки авторитетний у пам’яті сервера під час сесії й довговічно зберігається в записі сесії; синхронізація — цілісними знімками сцени (стирання = ознака «видалено»); повторне приєднання відновлює стан через `scene_init`.
