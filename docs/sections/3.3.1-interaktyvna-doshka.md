3.3.1 Реалізація інтерактивної дошки

(Примітка: діаграму класів винесено в окремий додаток. Літеру додатка слід узгодити з фінальним порядком додатків; у тексті нижче він позначений умовно як «додаток Х».)

Діаграма класів пакета «Інтерактивна дошка» наведена в додатку Х. Вона відображає реалізацію пакета, спроєктованого в підрозділі 2.6.1. У коді модулі пакета є об'єктами TypeScript, а не класами. На діаграмі їх показано як класи зі стереотипом «module». Модульний стан файлу маршрутів винесено в окремий клас RoomRegistry.

Клас WhiteboardRoutes обслуговує WebSocket-з'єднання. Метод upgradeWebSocket(appointmentId) приймає запит на з'єднання. Метод authenticate(headers) перевіряє сесію користувача через Better Auth. Далі WhiteboardRoutes викликає метод getForParticipant(appointmentId, userId) класу AppointmentsService. Він перевіряє, що користувач є учасником сесії і що сесія має статус «active». Якщо перевірка не пройдена, з'єднання закривається з кодом 1008. Метод parseMessage(raw) розбирає вхідне повідомлення і повертає null для некоректного. Методи onOpen(), onMessage(event) та onClose() обробляють відкриття з'єднання, повідомлення та закриття.

Клас RoomRegistry зберігає активні кімнати. Поле rooms містить одну кімнату на кожну сесію. Поле saveTimers містить таймер відкладеного збереження для кожної кімнати. Метод broadcast(room, sender, message) надсилає повідомлення всім учасникам кімнати, крім відправника. Метод scheduleSave(appointmentId, room) скидає таймер і запускає його знову на 3 секунди, задані константою SAVE_DEBOUNCE_MS. Збереження виконується лише тоді, коли протягом 3 секунд змін не було. Метод flushPendingSave(appointmentId, room) зберігає стан негайно, якщо таймер ще активний.
Клас WhiteboardService реалізує бізнес-логіку пакета. Метод loadState(appointmentId) повертає збережений стан дошки, а за його відсутності — порожній. Метод saveState(appointmentId, state) зберігає стан дошки. Метод clearState(appointmentId) очищує його. Сервіс передає запити до WhiteboardRepo.

Клас WhiteboardRepo виконує SQL-запити. Методи findStateByAppointmentId(), updateState() та clearState() читають і змінюють поля whiteboard_elements та whiteboard_files таблиці appointments. Обидва поля мають тип JSONB. Окремої таблиці для дошки немає, бо кожна сесія має рівно одну дошку.

Інтерфейс WhiteboardState описує стан дошки. Поле elements містить елементи малюнка, поле files — додані зображення.
